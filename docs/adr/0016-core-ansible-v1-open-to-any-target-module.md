# ADR-016 — `core.ansible/v1` open to any target module, not reserved for `base-os`

- **Status**: accepted
- **Discussion**: predates the issue-based process (ADR-049)

Context: `chrony` (milestone M6) must install and configure `chronyd` in server mode, a product-specific configuration that the generic `os.base/v1` contract (`Harden`, `TrustCA`, `SetResolver`, `SetNTP`) does not cover. Doc 07 lists `core.ansible/v1` only in the `requires` of `base-os`, but does not exclude it from other target modules; doc 03 describes it as a generic core function, available to any step that declares it in `requires`. Alternatives: extend `os.base/v1` with a generic `RunPlaybook`-style RPC that other modules would delegate to `base-os` (rejected: it would make `base-os` a mandatory intermediary for every target configuration, and couple its contract to each product's specific needs, the opposite of the principle of generic per-domain functions). Decision: any target-phase module may declare `core.ansible/v1` in its `requires` and run its own playbook, exactly as `base-os` does for the common configuration — `os.base/v1` stays reserved for the functional configuration common to every VM (CA, resolver, NTP client), each product handling its own installation/configuration through its own embedded playbook. Consequence: `chrony` (and the following target modules that need it, e.g. `powerdns`) declare `core.ansible/v1` in addition to `compute.vm/v1` and `os.base/v1`, beyond the minimal list of doc 07.
