# ADR-021 — Development process: atomic PRs merged with squash, Release Please

- **Status**: accepted; milestone and debt tracking completed by ADR-049
- **Discussion**: predates the issue-based process (ADR-049)

Context: up to M8, a whole milestone fitted in a single branch and a single PR, with one commit per logical step (the M8 PR held five distinct topics). These PRs are long to review, and `main` does not tell which commit matches which topic. The user adopts the process of their neossh project: issue and PR templates, PR titles validated as Conventional Commits, squash merges, Release Please, Dependabot, tests with the race detector.

Alternatives: (a) keep one PR per milestone with rebase merges to preserve the logical commits — rejected by the user: the PRs must be atomic, not just the commits; (b) enforce a closed list of commit scopes — rejected: a list of module names would require changing `.github/` for every new module, and a list limited to the core layers would deprive the CHANGELOG of the affected module's name; the scope therefore stays free and optional; (c) a single version for the whole repository — rejected: the SDK is a separate Go module, consumed by third-party modules, and needs its own `sdk/vX.Y.Z` tags; (d) publish binaries with GoReleaser right away — deferred: a multi-binary configuration (core + one binary per module) needs designing.

Decision: one PR = one topic, squash-merged; a milestone is split into several successive PRs. The PR title (validated by `semantic-prs.yml`) becomes the commit on `main`. Release Please manages two packages: the core (`vX.Y.Z` tag, version written to `internal/version`, which is used for the modules' `core` compatibility check) and the SDK (`sdk/vX.Y.Z` tag). Before 1.0: `feat` → patch, breaking change → minor, in line with SemVer 0.x. A minor release crosses the upper bound of the `core` constraints: the PR that introduces the breaking change raises the bound of the repository's modules if they remain compatible (found at the 0.2.0 release, whose SDK import path change did not touch the gRPC protocol; follow-up issue on the basis of this constraint). Dependabot covers the actions and every `go.mod` (one PR per dependency, across all modules). The main CI job runs the tests with the race detector (`make test-race`, CGO for tests only). `docs/PROGRESS.md` is no longer updated on every PR (a constant source of conflicts) but at the end of a milestone; debt lives in the `tech-debt` issues. Details in `CONTRIBUTING.md`; `AGENTS.md` points to `CLAUDE.md` without duplicating it.

Consequence: the `/milestone` command now splits the plan into atomic PRs. No PR is merged without the user's approval. Publishing binaries (GoReleaser) will be the subject of a later ADR.
